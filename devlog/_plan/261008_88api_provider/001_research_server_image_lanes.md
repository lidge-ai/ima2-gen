The new transport should be a sibling such as `lib/api88ImageAdapter.ts`. Its endpoint selection must depend on model family and reference presence while preserving the selected model byte-exact:

- GPT image generation → `POST /v1/images/generations`, JSON.
- GPT image editing/reference generation → `POST /v1/images/edits`, multipart image bytes.
- Gemini image generation/editing → `POST /v1/chat/completions`, including reference image data URIs in the image-content payload.
- Registered unverified Grok models → reject locally until enabled.
- Use the image key exclusively. Never reuse `ctx.openai`, the OpenAI family executor, Responses transport, Atlas prediction endpoints, or AtlasCloud’s automatic edit-model replacement.

Reference/result contracts need particular care:

- [lib/providers/execution/types.ts:10](lib/providers/execution/types.ts:10), lines 10–39: references are `{b64, declaredMime, detectedMime}`; `sourceImage` is a separate base64 string. These are neither buffers nor prebuilt data URIs.
- [lib/refs.ts:129](lib/refs.ts:129), lines 129–173: classic/multimode user references accept raw base64 or data URIs; validation removes the URI prefix and records declared/detected MIME. Global reference count currently defaults to **5**, so a larger provider limit alone does not raise accepted input capacity.
- Atlas classic uses the effective prompt; node/edit prepend `"Edit this image: "`. Node prepends its parent source to references. Atlas multimode and node use `rawPrompt`, dropping pipeline-added prompt context. Decide that deliberately for 88api; using `request.prompt` preserves element/background/size additions.
- [routes/edit.ts:85](routes/edit.ts:85), lines 85–102 and 262–266: with no mask, the source image bypasses `validateAndNormalizeRefs()` and is passed unchanged. PNG decoding with a mask validates source bytes but still does not replace `sourceImage` with normalized base64. Normalize the source at the new adapter/transport boundary before creating multipart bytes or Gemini data URIs.
- [lib/providers/execution/types.ts:49](lib/providers/execution/types.ts:49), lines 49–89: executors must return base64, not a bare URL. Download URL results before returning; carry detected MIME and optional URL.
- Classic/multimode/Agent Mode embed metadata and write image plus JSON sidecar. Edit writes returned/composited bytes directly at [routes/edit.ts:323](routes/edit.ts:323). Node calls `saveNode()` at [lib/nodeGeneration.ts:402](lib/nodeGeneration.ts:402). Node and Agent Mode currently discard upstream `providerUrl`; retaining that provenance would require additional result/meta plumbing.

No lane-specific switch addition is needed in `derive.ts`, the general execution types, or `execution/index.ts`: they derive or dispatch through the registry/factory. Keep `"88api"` outside the explicit OpenAI/Grok/Google family guards. `execution/legacy*.ts` are unsupported-provider fallbacks, not an implementation template.
